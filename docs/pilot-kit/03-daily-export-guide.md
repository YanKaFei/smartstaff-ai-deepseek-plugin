# 每日经营数据导出指引

## 原则

**店长不需要逐桌重复录入事件。** 能自动导出的由 POS/叫号系统导出；不能导出的由试点观察人员负责，店长只做每日反馈。

## 每日流程（建议闭店后 15 分钟）

1. 导出/收集当日经营事件：
   - 有 POS/叫号系统：导出 CSV/Excel，字段映射到 `R5-PILOT-EVENTS-TEMPLATE`；
   - 无系统：试点观察人员按事件表补录，优先保证入座/离店/清台；
   - 不要求店长逐桌抄写。
2. 检查事件表：
   - `event_id` 唯一；
   - 时间使用 `YYYY-MM-DDTHH:MM:SS+08:00`；
   - 不写顾客姓名/手机号/支付明细。
3. 观察人员完成当日工作量抽样（见 04）。
4. 店长填写每日反馈（见 05），内部人员代录。
5. 次日由试点团队导入系统；未授权/缺字段会进入质量报告。

## 自动化优先级

| 数据 | 优先来源 | 无法自动导出时 |
| --- | --- | --- |
| 叫号/入座/结账/离店/清台 | POS/叫号系统 | 试点观察人员补录 |
| 员工上下班 | 排班/考勤系统 | 观察人员按班次记录 |
| 服务员工作分钟 | 观察抽样 | 观察人员记录，不要求店长 |
| 店长判断 | 店长线下 | 内部人员代录 |

## 禁止

- 不把缺失时间按平均值补写；
- 不把同一事件重复导出为多条；
- 不上传含个人信息的原始小票/顾客资料；
- 不在未授权时导入。
