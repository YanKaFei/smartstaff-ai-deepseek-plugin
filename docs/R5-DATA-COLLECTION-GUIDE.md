# R5 烤肉店现场数据采集说明

> 适用：单店 14 天影子试点。只采集经营与工作量数据，不采集顾客姓名、手机号、支付明细。

## 1. 两种采集模式

### A. 经营事件数据

一行 = 一个事件：

- `queue_join` 取号
- `queue_call` 叫号
- `seat` 入座
- `checkout` 结账
- `leave` 离店
- `clean` 清台完成
- `staff_checkin` / `staff_checkout` 员工上下班
- `table_status` 桌台状态更新

文件：`R5-PILOT-EVENTS-TEMPLATE.csv` / `.xlsx`

### B. 员工工作量观察

一行 = 一个**具体服务动作**：迎宾、代烤、上菜、换盘、结账、清台等。

文件：`R5-WORKLOAD-TEMPLATE.csv` / `.xlsx`

## 2. 样本定义与去重

- 经营事件以 `event_id` 唯一；同一个事件重复抄写只能保留一次。
- 工作量以 `observation_id` 唯一；同一服务动作重复记录会被标记 duplicate，不重复计入总分钟。
- 一个服务过程可以拆成多个动作行（如迎宾 5 分钟、代烤 20 分钟、换盘 5 分钟），但每个动作必须有自己的 observation_id。
- 不把“整个班次”写成一条工作量；也不把同一动作复制到多个桌型。
- 无法确认的服务分钟留空，不按平均值补写。

## 3. 时间与岗位

- `occurred_at` / `start_at` / `end_at` 使用 `YYYY-MM-DDTHH:MM:SS+08:00`（或 CSV 中 `HH:MM` + `business_date`）。
- 事件按发生时间记录；允许补录，系统按时间排序，不要求手工排序。
- 员工只记录岗位和匿名工号（如 `S01`），不要记录姓名/手机号。
- 店长评价 `manager_sufficiency`：`short / adequate / over / unknown`；若店长能明确填写“合理需求人数”，填 `manager_required`。`short` 不会自动换算为人数。

## 4. 采集节奏

- 每天午市/晚市各检查一次事件完整性。
- 每桌至少：入座、结账、离店、清台；排队事件能记则记。
- 工作量观察建议每天抽 2–3 个时段，覆盖小/中/大桌和三种服务模式（若门店实际使用）。
- 每天结束前导出 CSV/XLSX，次日由内部人员导入。

## 5. 隐私与授权

- 门店使用匿名编号；顾客与员工个人信息不进入文件。
- 导入前确认试点档案 `authorizationStatus=authorized`。
- 未授权数据导入会被服务端拒绝（`PILOT_NOT_AUTHORIZED`）。
- 真实数据只用于本试点预测评估，不用于招聘/结算/处罚。

## 6. 缺失与异常

- 缺失时间/桌型/人数会进入质量报告；不会自动补写。
- 时间倒序、重复、手机号/邮箱出现会被标记 invalid；修正后重新导入。
- 质量报告作为评估输入，不作为真实经营结论。
